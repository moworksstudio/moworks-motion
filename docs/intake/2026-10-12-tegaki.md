# Intake: gkurt/tegaki

- **Read:** 2026-10-12, commit `32654a4cfb0fa6a2873264cf693316acd59d1627` (tag `tegaki@1.1.0`), https://github.com/gkurt/tegaki
- **Licence:** MIT (`LICENSE`, © 2026 Gokhan Kurt; renderer and generator packages MIT) · assets: 13 bundled fonts under SIL OFL 1.1
  except Hershey Script (Hershey Fonts terms: free use with the acknowledgements kept beside the data); **flags:** two shipped font subsets
  keep a Reserved Font Name (Parisienne, Nanum Pen Script), the KanjiVG stroke-order data the generator consults by default is CC BY-SA 3.0
  (share-alike), Make Me a Hanzi is under the Arphic Public License (copyleft), and an optional generator dependency compiles CGAL's
  GPL `Straight_skeleton_2` (details below)
- **What it is:** a TypeScript library that turns a font into animated handwriting. A generator reads the font's outlines and writes, per
  character, pen strokes (centre lines with widths) in a plausible writing order and with timing; a renderer (`TegakiEngine`, with
  React / Vue / Svelte / Solid / Astro / web-component wrappers) paints them on a canvas, and can also export SVG. Published on npm as
  `tegaki` (1.0 on 2026-09-30, 1.1 on 2026-10-11); the generator is a private package run from a checkout with Bun, or in the browser in
  the tegaki.ink Studio. 523 commits since 2026-03, one main maintainer, very active.

## Tóm tắt cho người dùng

**Có cần cho kit không? Có ích, khác hai repo trước.** Tegaki làm được một việc kit chưa làm được: **viết tay một dòng chữ bất kỳ, từng nét
theo đúng thứ tự bút, bằng font mình chọn**. Mẫu gần nhất của kit (`hand/write-title`, từ HyperFrames) chỉ có 75 ký tự ASCII của font
Caveat. Gặp chữ tiếng Việt có dấu, nó cho chữ hiện mờ dần thay vì viết, và lên After Effects thành ảnh. Chỗ cần thử trước: dữ liệu tegaki
có sẵn **không có chữ tiếng Việt nào**. Phải tự sinh dữ liệu từ một font có tiếng Việt, và chưa ai thử ơ, ư, đ ra sao.

What only Tegaki does: centre lines, widths, order and timing taken from the font itself (accents written after their letter, dots
deferred per word), for a client's own font too. What only the kit does: the film's clock, After Effects, Vietnamese everywhere, the
film's own text and fonts, brush textures.

## Not taken, and why

- **The runtime as shipped (option 4).** It paints a `<canvas>` over its own DOM text overlay, measures layout with a ResizeObserver,
  loads fonts and the optional harfbuzz shaper asynchronously, and ships as ES modules (`build.py` writes classic `<script src>` tags). It
  is seekable in controlled mode (`time: number`; `engine.update({ time })` repaints synchronously, `engine.ts:1000-1011`; default seed 0;
  `requestAnimationFrame` and `performance.now` only in uncontrolled mode), so it could run on the film's clock, but After Effects would
  get a picture sequence (KI-10) and the npm package is 76 MB (fonts and glyph JSON). Reconsider only if its plugins (taper, glow,
  per-letter variation, clip to the letter shape) are wanted more than editable AE layers.
- **The shipped bundles.** The four Latin bundles (Caveat, Italianno, Tangerine, Parisienne) hold the 90 ASCII glyphs only; checked:
  0 of the 67 lowercase Vietnamese letters in every bundle except Hershey Script and EMS Allure (18 of 67). Parisienne and Nanum Pen
  Script subsets keep their Reserved Font Names (upstream `OFL.txt`: "with Reserved Font Names "Parisienne"" / "Nanum … NanumPen"),
  which the OFL forbids for modified versions; Tegaki's `FONTS-LICENSE.md` does not mention it. CJK, Arabic, Hebrew, Indic bundles are
  not needed.
- **The generator's code.** Private package, Bun only, network at generate time unless `--font-file` is given and the online datasets are
  left out; its optional `@matthewjacobson/str8` dependency (npm: MIT) compiles CGAL's `Straight_skeleton_2`, which its README calls
  GPL. It loads only for `extraction: 'partition'` with `medialMethod: 'straight-skeleton'` (`commands/generate.ts:635-637`) and the
  report commands, not on the default `ink-graph` path. Use the generator as an outside tool on the desktop; never vendor it.
- **Website demo plugins** (chalk, brush, neon, wet ink…): MIT but not in the package; the kit has its own textures.

## Risks and open questions

1. **Vietnamese quality is unknown (row 1 decides).** The generator treats an accent as a separate mark written after the letter body when
   it does not touch the body (`packages/generator/src/geometry/marks.ts:1-30`, Latin letters that decompose under NFD). Expected:
   circumflex, breve, tone marks and the dot below come after the letter, good. The horn of ơ / ư touches the body, so it is written as part
   of the letter by the heuristic order; đ / Đ do not decompose, so the bar is ordinary ink. Both are untested upstream.
2. **Licence of generated data.** Stroke data derived from a font's outlines is safest treated as part of the font under the OFL: ship the
   font's `OFL.txt` with it, never under a Reserved Font Name. Patrick Hand and Sedgwick Ave Display (both in `engine/vendor/fonts/google/`,
   Vietnamese complete) have no Reserved Font Name in their `OFL.txt` header; Lobster and Quicksand do.
3. **Share-alike risk from KanjiVG.** The generator consults all reference datasets by default (`DEFAULT_REFERENCE_DATASETS =
   REFERENCE_DATASET_IDS`), KanjiVG included, whose description reads "also print Latin and digits". Upstream says reference polylines
   never enter the bundles, but whether a stroke order chosen by matching CC BY-SA data makes the result an adaptation is unclear. Avoid
   the question: generate with `--reference-datasets` naming only `letterpaths-print`, `letterpaths-cursive` (Robin Linacre, MIT,
   embedded at `88c9e08`, "consultation-only … never enter generated bundles", `letterpaths-data.ts:1-12`) and `punctuation`
   (Tegaki's own, MIT); leave out `hershey-*` too (free with acknowledgement, a third set of terms for no clear gain on Latin), and
   never `kanjivg` or `makemeahanzi`
   (`packages/generator/src/stroke-order/datasets.ts:19-83`).
4. **A client's own font.** The generator works on any TTF / OTF, but a commercial brand font's licence may not allow deriving data from
   it; ask per font (the kit's brand packs stay local).
5. **Generation time and Windows.** Not documented; the repo's CI runs on Ubuntu only. Bun supports Windows; to confirm in row 1.

## Build notes for the desktop session

**Row 1: the trial (outside the kit, nothing committed)**
- Clone `gkurt/tegaki` at `32654a4` (or a later tag), `bun install`, then from the repo root
  `bun start generate --font-file <kit>\engine\vendor\fonts\google\PatrickHand\PatrickHand-Regular.ttf -c "<ASCII + every Vietnamese letter, both cases>" --reference-datasets <the three ids in risk 3> -o out\patrick-hand`
  (flag names as in `AGENTS.md:95-97` and `src/commands/generate.ts`; check `--help` for how a list is written). Keep the default `geometry` pipeline and `ink-graph` extraction (str8 is then
  never loaded). The Studio at tegaki.ink/studio runs the same generator in the browser if Bun is a problem (it fetches the page from
  the web; the font stays in the browser according to the site, not verified here).
- Look at: `ă â ê ô ơ ư đ Đ`, stacked marks `ằ ẩ ộ ữ ỡ`, capitals `Ấ Ở`, and a sentence. Time the run. Write down the result in this file
  or the CHANGELOG before building row 2.

**Row 2: preset `text/handwrite`** (effect on a text element)
- Data: the generated `glyphData.json` (format: `packages/renderer/src/types.ts:107-216`: per character `{ w, t, s: [{ p: [[x, y, width]],
  d, a, r?, n? }] }`, font units, y down, origin on the baseline) in the preset's `assets/`, with the font's `OFL.txt`, a credit line and
  SHA-256 in `source.sha256`. If a shipped Latin bundle is ever used as is: `packages/renderer/fonts/<font>/glyphData.json` +
  `FONTS-LICENSE.md` + the root `LICENSE`, with checksums.
- Layout: `ctx.split(el, "chars")` gives one span per character (the browser's own layout, kerning, wrapping, Vietnamese); for each span,
  `glyphData[char]` (NFC) placed at the span's left edge and baseline, `scale = fontSize / unitsPerEm`; one `<path>` per stroke made with
  `ctx.make`, round caps and joins, width = the stroke's mean width × scale; dots as circles. The film's own text stays underneath at
  opacity 0 (or as a fill revealed after the stroke) so the end frame matches the layout (`check_end`).
- Timing: port the grapheme path of `packages/renderer/src/lib/timeline.ts:146-623` (`glyphGap` 0.1 s, `wordGap` 0.15 s, `lineGap` 0.3 s,
  deferred dots / marks) and use each stroke's `d` (delay) and `a` (duration); the generator's speed is stroke length ÷ 3000 font units per
  second with a 0.15 s pause between strokes (`packages/generator/src/constants.ts:211-219`). Default stroke ease is ease-out quad
  (`packages/renderer/src/lib/easings.ts:21-23`) = GSAP `power1.out`. A `speed` param scales every time.
- Tweens: per stroke `tl.set(path, { visibility: "visible" }, start)` and `tl.fromTo(path, { strokeDashoffset: L }, { strokeDashoffset: 0,
  duration, ease: "power1.out" }, start)` with `stroke-dasharray: L` and `L` rounded to 4 decimals: literal tweens, so `seek`, `bake` and
  `end` checks apply. No `ctx.code` needed.
- Demo: a Vietnamese headline ("Viết tay từng nét chữ"), thumbnail mid-write. Gallery check on this preset only.
- Reference for the maths (do not copy as shipped unless the build chooses to): `src/lib/strokeTimeline.ts:143-185, 280-295`,
  `src/lib/svgExport.ts:233-401` (dash keys, nib stamps, dots).

**Row 3: After Effects Trim Paths**
- Today `engine/ae/record.js` and `ae_runtime.jsx` have no `stroke-dasharray` / `stroke-dashoffset` handling (searched: no "dash" or
  "trim"); SVG paths become shape layers with a static stroke. Record the dash offset per frame, write a Trim Paths with End keyed from
  `1 - dashoffset / L` on the shape layer. Until then the preset is `"ae": "png"`.
- Tests: `engine/tests/ae/run_cases.py` with a case expecting shape layers with Trim Paths End keys; `line/hw-underline` may gain from it
  too (re-check its AE result).
